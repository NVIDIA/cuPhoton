9  Run the transient chain

The cuPhoton checkout ships an end-to-end pipeline in examples/transient-chain/. It takes a target image and its reference from FITS files to a catalog of candidates, each with a position, a flux, their error bars and, with a classifier checkpoint, a real-or-bogus score. Each GPU worker keeps the main image calculations on the device. Astropy reads begin on the host, and WCS work, optional host star finding, diagnostics and final catalog columns can cross the host/device boundary. Use it to run the whole pipeline on your own images instead of calling each module as in Chapter 2. The chain needs an NVIDIA GPU. Its configuration, input checks and file loaders run on a CPU, and this page runs them on the sample pair.

The worker runs these steps for each target image:

Step Stages in summary.json Module What it does
Read read Core, xDR reads the target and reference planes with the reader set in io.reader
Align template, refine xRep reprojects the reference onto the target grid, then corrects the mapping with matched stars
Subtract mask, xpois xPois masks bad pixels, fits the blur-matching kernel and subtracts
Detect detect, stamps the example finds residual hotspots and cuts target, kernel-matched reference (including fitted background), and difference stamps around each
Measure xfit, uncertainty xFit fits a dipole to each candidate, sets quality flags and measures a PSF flux
Error bars uq xPois, xRep adds the noise terms that the fit leaves out
Classify xscan xScan scores the cutouts, only when you pass a checkpoint

You need:

  • A cuPhoton source checkout with any profile (Chapter 1). Run the blocks from its root, or set CUPHOTON_REPO to its path.
  • For the chain: a Linux host with an NVIDIA GPU and the gpu and catalog extras, plus dragon or mpi for those executors.
  • A target and a reference image as FITS files with WCS headers (world coordinate system: the mapping from pixel to sky position). Most of the error budget also needs a variance plane for each.
  • Optional: an xScan checkpoint (Chapter 8).

9.1 Make a sample pair

The block below writes sample/reference.fits and sample/target.fits, the pair of Chapter 2.

Create the sample pair (NumPy and Astropy only) 
# Writes sample/reference.fits and sample/target.fits: two synthetic star fields
# of the same sky on different pixel grids, with different blur and sky level.
# The target also holds one new source and one star three times brighter.
# Noise is independent Gaussian noise with variance expected_image / gain;
# this teaching sample has no read noise, saturation, or detector artifacts.
from pathlib import Path

import numpy as np
from astropy.io import fits
from astropy.wcs import WCS

rng = np.random.default_rng(7)


def make_wcs(shape, scale_arcsec, rotation_deg, crpix_shift):
    w = WCS(naxis=2)
    w.wcs.ctype = ["RA---TAN", "DEC--TAN"]
    w.wcs.crval = [150.0, 2.0]
    w.wcs.crpix = [shape[1] / 2 + crpix_shift[0], shape[0] / 2 + crpix_shift[1]]
    c, s = np.cos(np.radians(rotation_deg)), np.sin(np.radians(rotation_deg))
    w.wcs.cd = scale_arcsec / 3600 * np.array([[-c, s], [s, c]])
    return w


def render(shape, wcs, ra, dec, flux, sigma, sky, gain):
    x, y = wcs.world_to_pixel_values(ra, dec)
    yy, xx = np.mgrid[: shape[0], : shape[1]]
    image = np.full(shape, sky, dtype=float)
    for xi, yi, fi in zip(x, y, flux):
        image += fi / (2 * np.pi * sigma**2) * np.exp(-((xx - xi) ** 2 + (yy - yi) ** 2) / (2 * sigma**2))
    return rng.normal(image, np.sqrt(image / gain)).astype(np.float32)


ra = 150.0 + rng.uniform(-0.016, 0.016, 150)
dec = 2.0 + rng.uniform(-0.016, 0.016, 150)
flux = 10 ** rng.uniform(2.5, 4.5, 150)
target_flux = np.r_[3 * flux[0], flux[1:], 4000.0]  # star 0 brightens; one new source
target_ra, target_dec = np.r_[ra, 150.004], np.r_[dec, 2.003]

Path("sample").mkdir(exist_ok=True)
for name, shape, wcs, sky_coords, fl, sigma, sky, gain in [
    ("reference", (300, 300), make_wcs((300, 300), 0.26, 0.0, (0, 0)), (ra, dec), flux, 1.2, 100.0, 8.0),
    ("target", (256, 256), make_wcs((256, 256), 0.27, 3.0, (4.3, -2.7)), (target_ra, target_dec), target_flux, 1.8, 120.0, 2.0),
]:
    header = wcs.to_header()
    header["GAIN"] = (gain, "electrons per data number (DN)")
    header["PSFSIG"] = (sigma, "Gaussian PSF sigma [px]")
    fits.writeto(f"sample/{name}.fits", render(shape, wcs, *sky_coords, fl, sigma, sky, gain), header, overwrite=True)

The correlation term of the chain’s error budget requires a locally translation-only mapping. When that term is active, a rotated or rescaled grid gives undefined error bars (Section 9.11.1). Write a second target that keeps the reference’s pixel scale and orientation, with the same two changes:

wcs = make_wcs((256, 256), 0.26, 0.0, (4.3, 6.3))  # the reference's scale, no rotation, shifted by a few pixels
header = wcs.to_header()
header["GAIN"], header["PSFSIG"] = 2.0, 1.8
image = render((256, 256), wcs, target_ra, target_dec, target_flux, 1.8, 120.0, 2.0)
fits.writeto("sample/chain-target.fits", image, header, overwrite=True)

9.2 Install the example

The example is a separate package inside the checkout. Start with the GPU environment from Chapter 1, which includes the catalog dependencies, then install the example from the checkout root. For a distributed executor, include --extra dragon or --extra mpi in that environment’s sync command. A later uv sync removes the example, so install it again after each sync.

uv pip install -e examples/transient-chain

On a CPU machine you can skip the install. The block below imports the example from the checkout, as launch.py does.

import os
import sys
from pathlib import Path

REPO = Path(os.environ.get("CUPHOTON_REPO", "."))
EXAMPLE = REPO / "examples" / "transient-chain"
sys.path.insert(0, str(EXAMPLE))  # not needed after you install the example
print(sorted(p.name for p in EXAMPLE.iterdir() if p.suffix in (".py", ".yaml")))
['compare_catalogs.py', 'config-generic.yaml', 'config.yaml', 'launch.py', 'repeat_catalogs.py']

launch.py starts a run, and the two YAML files hold every step’s parameters.

9.4 Describe your files to the survey adapter

The survey block picks an adapter, the code that turns one entry of the selections file into image planes. The generic adapter reads each plane from a file and an HDU (header/data unit; here, an image inside a FITS file) that you name. The template is the reference image. Print the layout that config-generic.yaml ships:

params = generic["survey"]["params"]
print(pd.DataFrame({"target": params["target"], "template": params["template"]}).to_string(na_rep=""))
print("identity:", params["identity"], " extra_keys:", params.get("extra_keys"), " mask_policy:", params["mask_policy"])

path_key                      image    template
image_hdu                         0           0
mask_path_key                  mask        None
mask_hdu                          0        None
variance_path_key            weight        None
variance_hdu                      0        None
variance_kind      inverse_variance    variance

A key that you leave out takes the adapter’s default, not the shipped value. Replacing the whole params block, as the next steps do, therefore drops the shipped identity, extra_keys and variance_kind. The defaults are the following.

Key Meaning
path_key, mask_path_key, variance_path_key the key of a selections entry that holds the file path
image_hdu, mask_hdu, variance_hdu an HDU index, an EXTNAME, or null for the first 2D image. An HDU without a path key reads the image’s own file. A plane with both null is absent
variance_kind variance, inverse_variance (a weight map) or none
on_target_grid false reprojects the reference through its WCS. true takes a reference already on the target grid
pieces how the variances of overlapping reference pieces combine: correlated or independent
identity the entry keys that fill the catalog’s exposure_id, ccd_id and band
mask_policy the mask bits that mark a bad pixel: none, strict (any nonzero bit), a survey preset, {planes: [...]} or {bits: N}

9.5 Give each image a variance plane

The sample pair has no variance planes. Approximate its Gaussian noise variance from the positive, sky-inclusive image and gain (electrons per data number), as in Chapter 2. Real data need their calibrated noise model, including sky and read noise:

import numpy as np
from astropy.io import fits

for name in ("chain-target", "reference"):
    image, header = fits.getdata(f"sample/{name}.fits", header=True)
    fits.writeto(f"sample/{name}_variance.fits", np.clip(image, 0, None) / header["GAIN"], overwrite=True)

9.6 Write a configuration for your files

Copy config-generic.yaml and replace its survey parameters. Each sample image sits in its primary HDU, with one variance file and no mask. Keys that you leave out take the adapter’s defaults.

import yaml

config = yaml.safe_load((EXAMPLE / "config-generic.yaml").read_text())
config["survey"]["params"] = {
    "target": {"path_key": "image", "variance_path_key": "image_variance"},
    "template": {"path_key": "template", "variance_path_key": "template_variance"},
    "mask_policy": "none",
}
config["align"]["xcorr_window_px"] = 128  # keep the alignment check's central window inside the 256 px target
config["stamps"]["stamp_size"] = 31  # the default 51 drops candidates within 25 px of the edge of this small image
Path("sample/chain.yaml").write_text(yaml.safe_dump(config, sort_keys=False))

9.7 Write the selections file

The selections file lists one entry per target image. Each entry holds the identity keys (exposure_id, ccd_id and band by default) and the path keys that you named. Each process reads a relative path from the directory it starts in. Write absolute paths.

import json

entry = {"exposure_id": 1, "ccd_id": "S1", "band": "r"}
for key, name in [("image", "chain-target"), ("image_variance", "chain-target_variance"),
                  ("template", "reference"), ("template_variance", "reference_variance")]:
    entry[key] = str(Path(f"sample/{name}.fits").resolve())
Path("sample/selections.json").write_text(json.dumps({"selections": [entry]}, indent=1))

9.9 Look at what the adapter reads

Run the adapter’s loaders with a host reader. load_target returns the target planes. template returns a provider whose build reprojects the reference onto the target grid with xRep, as the worker does on the GPU.

from transient_chain.fitsio import PlaneReader
from transient_chain.surveys import make_adapter

cfg = load_config("sample/chain.yaml")
adapter = make_adapter(cfg["survey"])
reader = PlaneReader("astropy", device=False)  # NumPy arrays; the worker reads to the GPU
target = adapter.load_target(entry, reader)
provider = adapter.template(entry, target, reader, mapping_grid_step=cfg["align"]["mapping_grid_step"])
template, template_bad, coverage = provider.build()
print(target.shape, template.shape, "variance planes:", target.variance is not None, provider.has_variance)
(256, 256) (256, 256) variance planes: True True

9.10 Run the chain on a GPU

On the GPU host, run the blocks above, then start the chain from the root of the checkout. The local executor runs the items in turn, in this process, on one GPU. This command needs a GPU and is not run here.

python examples/transient-chain/launch.py --executor local \
    --config sample/chain.yaml --selections sample/selections.json --output-dir out

Without --checkpoint-dir, the chain skips the classify step. To score the cutouts, pass the directory that holds an xScan checkpoint.pt. To change one value for one run, add --set block.key=value, such as --set io.reader=astropy.

For many images on several GPUs, pick another executor (Chapter 14):

Executor Start it with Workers
local python launch.py this process, one GPU
dragon the dragon launcher one persistent worker per GPU, placed by DragonHPC
mpi mpirun and cuphoton-openmpi-rank-exec one worker per MPI rank, one GPU each 
# Dragon, one node, one worker per GPU
dragon -s -t tcp -o tcp examples/transient-chain/launch.py --executor dragon \
    --config chain.yaml --selections sel.json --output-dir runs --name probe --max-workers 4

# MPI (Open MPI), one GPU per rank
CUDA_VISIBLE_DEVICES=0,1,2,3 mpirun -n 4 --map-by slot --bind-to none -x CUDA_VISIBLE_DEVICES \
    cuphoton-openmpi-rank-exec -- python examples/transient-chain/launch.py --executor mpi \
    --config chain.yaml --selections sel.json --output-dir runs --name probe-mpi

9.11 Read the catalog and the summary

The local run writes out/items/<item>/catalog.parquet and summary.json for each item, and out/catalog.parquet with the rows of all items. Dragon and MPI write the same files under <output-dir>/<name>/. Every item writes the same columns with the same types, also when it finds no candidates. Print the column count, the flux columns and the error terms:

from cuphoton.xfit import GaussianDipoleModel
from transient_chain import catalog

columns = catalog.schema(GaussianDipoleModel((51, 51)).parameter_names)  # the worker's dipole model
print(len(columns), "columns")
print([name for name in columns if name.startswith("psf_flux")])
for term, meaning in catalog.BUDGET_TERMS.items():
    print(f"{term:7} {meaning}")
93 columns
['psf_flux', 'psf_flux_err_fit', 'psf_flux_err', 'psf_flux_err_corr', 'psf_flux_err_kfit', 'psf_flux_err_kmatch', 'psf_flux_err_mis']
corr    correlated reference noise through the resampling and the kernel
kfit    the kernel fit's own uncertainty
kmatch  kernel mismatch times the reference flux (psf_flux only; 0 for positions)
mis     residual misalignment (0 for psf_flux)

The columns you are most likely to use:

Column Meaning
candidate_id cu-<exposure_id>-<ccd_id>-<index>
x, y rounded hotspot centroid on the target grid, in zero-based pixels
ra, dec sky position in degrees, from the target header WCS at (x, y), rather than the fitted source position
sign sign of the hotspot’s peak residual: +1 for a positive excursion, -1 for a negative excursion
source_x, source_y position of the measured source in pixels, relative to (x, y)
psf_flux difference flux at the source, in target image units; normally forced PSF (point spread function) photometry. It requires a variance plane and an independent PSF width. Without that width, an accepted one-lobe fit supplies its fitted flux; other rows are NaN
fit_model "dipole", or "single" for a candidate refit with one lobe
quality_flags bits of cuphoton.xfit.DipoleQualityFlag, 0 when none is set
probability, decision classifier output, NaN and false without a checkpoint

9.11.1 Error bars

The budget covers center_x, center_y, positive_x, positive_y and, when forced photometry runs, psf_flux. For each computed quantity q, use <q>_err: the quadrature sum of <q>_err_fit and the available terms above. It is NaN where fewer than half the pixels in a required window are usable, the correlation factor is undefined, or the total uncertainty is non-finite. A center needs both lobe windows to pass.

With the budget enabled, uq_valid means that every computed budget quantity has a defined error. It does not certify that every term was available, that the source model is appropriate, or that unavailable PSF photometry has a valid error. If a one-lobe fitted flux stands in for missing forced photometry, it keeps its fit-only error. Inspect summary.json for excluded terms and quality_flags for fit problems.

source_x_err and source_y_err normally copy the positive_* bars. For a fading candidate identified by the lobe-support flags whose one-lobe refit was not accepted, source_* instead selects the dipole’s negative lobe and its position errors are NaN: the budget was computed for the positive lobe.

When corr is active, its factor is undefined where the grid mapping between the two images is not locally a shift, for example a reference that is rotated or has a different pixel scale. The affected computed quantities get NaN error bars and uq_valid is false. summary.json counts them under uq.undefined_factor, and those on a rotated grid under uq.rotated_grid. The example’s README explains why. This page’s sample target shares the reference’s pixel scale and orientation for that reason.

After a GPU run, inspect the rows and read how the item’s bars were built. This block needs a finished run and is not run here.

table = pd.read_parquet("out/catalog.parquet")
columns = ["x", "y", "fit_model", "quality_flags", "psf_flux", "psf_flux_err", "source_x_err", "uq_valid"]
print(table[columns].to_string())

summary = json.loads(Path("out/items/S1-v1/summary.json").read_text())
print(summary["candidates"], summary["psf_sigma_source"], summary["uq_terms"])
if summary["uq"] is not None:  # null when there are no candidates
    print(summary["uq"]["excluded"])  # each term left out, with the reason

A candidate can have a finite flux error and still have uq_valid=False because a position error is undefined. Check quality_flags and fit_model before quoting a position. The one-lobe refit is attempted only when exactly one lobe is unsupported, and its result replaces the dipole position only when the refit covariance is valid. Rows with both lobes unsupported keep their dipole values and need further inspection.

psf_sigma_source reports where the PSF width came from. If uq.excluded reports mis: no misalignment model, inspect diagnostics.align.refine.misalignment.reason for the cause. These GPU result fields are described from the implementation; this page’s executable examples validate the CPU setup and input loading.

summary.json also records the reader each file took (diagnostics.read.receipts), the time per stage (timings_sec) and the bytes copied to the host (transfers).

9.12 Turn the error budget on or off

The uq block controls the error budget, which is on by default. The second argument of load_config takes the same overrides as --set. Compare the shipped block with the one that uq.enabled=false gives:

print(pd.DataFrame({"shipped": generic["uq"], "uq.enabled=false": fit_only["uq"]}).to_string())

measure_correlation      True             True
correlation_positions    1000             1000
sky_astrometry_arcsec    None             None
sky_astrometry_source    None             None

Key Effect when false (or set)
enabled every <q>_err equals <q>_err_fit, the term columns are 0, uq_valid is true, no candidate is refit with one lobe, and summary.json lists only fit under uq_terms
kernel_fit leaves out the kfit term
measure_correlation skips the per-image measurement of the correlation factor
single_source_refit keeps the dipole fit for candidates with one supported lobe

python examples/transient-chain/launch.py --executor local --config sample/chain.yaml \
    --selections sample/selections.json --output-dir out-fit-only --set uq.enabled=false

With uq.enabled=false, uq_valid is always true; inspect the fit validity flags and finite error values before using those fit-only errors.

A term also needs its inputs. corr needs both variance planes, and kmatch and mis need stars that the align step matched. Uncertainty quantification explains each term.

9.13 Options

Common launch.py flags are listed below. Run python examples/transient-chain/launch.py --help for the complete list, including worker and rank timeouts.

Option Default Effect
--executor required local, dragon or mpi
--selections, --output-dir required the selections file and the output folder
--config config.yaml next to launch.py the configuration file
--set BLOCK.KEY=VALUE none overrides one configuration value, repeatable
--checkpoint-dir none folder with an xScan checkpoint.pt. Without it the chain does not classify
--only CCD[/EXPOSURE] every entry runs only the matching items, repeatable

--max-workers one per visible GPU dragon only
--warmup-rounds, --measure-rounds none benchmark rounds under rounds/, dragon and mpi only

Check these configuration keys for new data.

Option Default Effect
io.reader auto auto decodes on the GPU with xDR when the file allows it, else with Astropy. xdr insists on the GPU decoder. astropy decodes on the host
align.star_finder gpu daofind finds stars with Photutils on host copies

stamps.stamp_size 51 in both files odd cutout size, equal to the checkpoint’s image_size. Candidates closer than half of it to the image edge are dropped
align.xcorr_window_px 512 side of the central window of the alignment check. It must fit inside the target
align.star_fwhm_px, align.star_threshold_sigma, align.match_radius_px 4.0, 20.0, 8.0 star finding and matching for the alignment refinement and the PSF measurement. Set them for your seeing, depth and astrometric accuracy
subtract.basis_sigmas [1.5, 3.0, 6.0] the kernel’s Gaussian widths in pixels. Chapter 6 shows how to pick them from the two PSF widths
subtract.template_bad_dilation_px 0 grows the reference’s bad-pixel mask by this many pixels. The README’s “Known issues” says when to set it
classify.noise_reference_sigma set for the checkpoint the chain was built with change it with the checkpoint, or set classify.apply_noise_match: false

9.14 Troubleshooting

Message Cause and fix
ModuleNotFoundError: No module named 'cupy' The host has no GPU stack. Install the gpu extra on a GPU host
config block 'uq' has unknown keys ['enable'] A misspelled key, in the file or in --set. The message lists the valid keys
selection 0 (S1-v1): 1 input file(s) not found The chain checks every path before it starts. The message names the first missing file
selection 0 lacks keys [...] The entry misses a key that the adapter needs. The message lists every key the adapter needs
--only [...] matched nothing A token is CCD or CCD/EXPOSURE, such as S1 or S1/1
checkpoint image_size ... != stamps.stamp_size ... Set stamps.stamp_size to the checkpoint’s image size

With io.reader: xdr, a RICE-compressed, scaled or quantized image fails before any pixel is read. Use auto.
